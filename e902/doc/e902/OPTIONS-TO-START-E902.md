# 让 E902 跑起来的可执行选项（决策包）

日期：2026-09-22 · 前置阅读：`FINDINGS-LEDGER.md`（T1–T12）、`BL31-PATH-RUNBOOK.md`、`RISCV-IMPACT`（见 `RECOVERY-AND-HANDOFF.md` §7.2）

**已确认的事实（不再重复论证）**：软件侧没有 E902 内核复位位；`RISCV_BGR` bit0 只是时钟门控；
这版 u-boot **没有** `smc` 命令；CPUS 电源域控制寄存器未公开。所以要让内核执行我们的代码，
**必须动启动介质**，或者改 u-boot 后刷写。

下面两条路都可执行，差别只在风险与所需现场条件。

---

## 选项 1（推荐）：改 u-boot + 重刷 bootloader，让 bl31 载入我们的固件

**思路**：bl31 在启动时把 `scp.fex` 拷到 `0x40004000`、设 `RST_START_ADDR`、放复位。
把 `scp.fex` 换成"会与 bl31 握手"的我们的镜像，bl31 就会启动我们。

**要做的**：
1. **先实现握手**（这是之前失败的原因）。看 `scp.fex` 启动后最先写哪里：
   - 已排除"固定 SRAM magic 字"（`strings`/反汇编无命中）；
   - 倾向于是**一条 mailbox 消息**（`scp.fex` 里 `40007334 lui a4,0x3004` → 写 `0x03004000`）；
   - 需要从 bl31 的 `arm_svc_arisc_wait_ready` 语义反推（bl31 闭源，可用"改一处、看 bl31 行为"的方式逐步逼近）。
   起点素材：`e902/e902-fw-scp/`、`e902/scp-ours.bin/elf`、`e902/apply-scp.sh`、`e902/preflight-image.sh`。
2. 重新打包并刷写 bootloader（或按 `userpatches/u-boot/.../0001-*.patch` 路线）。
3. **刷写前必须**：确认能物理恢复（`e902/backup/sd-boot-head.img` + `e902/restore-sd-auto.sh`），并确认真实启动介质（SD 还是 eMMC：板上 `/dev/mmcblk1p1` 是根，需确认 boot0 来源）。

**可检查的成功判据**：板子启动后，**板子自己的 `/dev/ttyUSB0`**（FT232H = E902 控制台）出现
`=== A733 E902 firmware v2 ===` 横幅；同时 `awdevmem.py read 0x07032204` 读到我们设的向量、
SRAM `0x4001E000` 出现 `0xE902C0DE`。

**回滚**：SD 引导头备份写回 / `restore-sd-auto.sh`。
**风险**：bl31 等握手时挂住 → 需断电重启（现场条件）。

---

## 选项 2：重编 u-boot，打开 `CONFIG_CMD_SMC`，用 u-boot 控制台手动启动

**思路**：u-boot 源码里 `cmd/smccc.c` 已具备 `smc <fid> [args]`，只是没编进去。
打开后，在 u-boot 提示符里：
```
# 在 u-boot 里把固件写进 SRAM_A2（ARM 视角 0x00060000 = E902 0x40020000）
mw.b 0x00060000 ...            # 或用 loady 从串口灌
# 设复位向量 + 触发 bl31 启动流程
mw.l 0x07032204 0x40020000
smc 0x8000ff10 0 0 0
```
**优点**：不替换 `scp.fex`，理论上可反复试。
**缺点**：仍需重刷 u-boot（属于启动介质写入）；仍需握手否则可能挂住；
`smc 0x8000ff10` 的语义（参数是 `dts_cfg_64` 指针还是别的）需实测确认
（`bootm.c:409` 传的是 `r2`，`arisc.c:274` 传的是 `&dts_cfg_64`，两者不一致，需实验分辨）。

---

## 选项 3（不推荐，仅登记）：盲写未公开的 `S_SPC`(0x07002000) 找 CPUS 域复位

手册没有 `S_SPC` 的寄存器清单。盲写未公开电源/复位寄存器可能造成不可预测的硬件状态，
**本轮未执行，也不建议在没有厂商文档或逻辑分析仪的前提下尝试**。

---

## 建议顺序

1. 先确认**物理恢复条件**（能插卡 + 能断电重启）；
2. 从选项 1 的"握手"入手做**离线**分析（不动板子，零风险）；
3. 握手实现后，选一个现场窗口执行选项 1（或 2），并当场验证回滚。
