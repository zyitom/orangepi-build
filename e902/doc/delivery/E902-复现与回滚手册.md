## 2. 刷写（两条路径，选其一）

**铁律**：待刷镜像必须**恰好 105912 字节**；刷写前确认回滚件在位（§4）。

### 路径 A（推荐，零板险）：SD 卡在 TL101 读卡器里
```bash
cd ~/Desktop/orangepi-build
sudo -v      # 预先输入 TL101 的 sudo 口令
# 识别：确认 /dev/sdX 是板卡（eGON.BT0@0x2004 + sunxi-package@0x1004000）
sudo dd if=/dev/sdX bs=1 skip=$((0x2004))  count=8  status=none   # → eGON.BT0
sudo dd if=/dev/sdX bs=1M count=24 status=none | sha256sum        # 记录头哈希
# 外科写入 + 读回校验
sudo dd if=e902/fw-out/scp-ours-padded-105912.bin of=/dev/sdX bs=1 seek=$((0x113BC00)) count=105912 conv=notrunc status=none
sudo sync
sudo dd if=/dev/sdX bs=1 skip=$((0x113BC00)) count=105912 status=none | sha256sum
# → 必须等于 e902/fw-out/SHA256SUMS 里的 8aaf9486…
# ★ T22 必做：改过槽位内容后，必须重算启动包 add_sum（boot0 会校验整包）：
python3 e902/tests/fix-bootpkg-sum.py /dev/sdX --write   # 期望写入 83f86015，读回 PASS
```

### 路径 B：板子能正常启动时，板上刷写
```bash
export BOARD_PASS=orangepi
S=~/Desktop/orangepi-build/ar0234-port/tools/ssh_board.sh
cat e902/fw-out/scp-ours-padded-105912.bin | $S 'cat > ~/e902v2/scp-ours-padded.bin'
printf 'orangepi\nYES\n' | $S "sudo -S sh /home/orangepi/e902v2/flash-scp.sh /home/orangepi/e902v2/scp-ours-padded.bin /dev/mmcblk1"
# 脚本自带：尺寸校验 → 写入 → 读回哈希比对
```

## 3. 上电验证与演示（一键）

```bash
# 把卡插回板子、上电，然后：
bash e902/tests/post-poweron.sh
```
该脚本自动：等 ssh（240s）→ 推送 awdevmem.py → 后台抓 E902 控制台（FT232H）50s → 心跳块读两次（间隔 10s，看 seq 增长）→ 读 RST_START/RISCV_BGR/两侧 mbox 状态 → 依次发 PING/ECHO/SPI_READ/UART_STAT 并读回复 → 从 TL101 向 S_UART0 注入 `xyz\n` 再查 UART 计数（证明 RX 中断）→ 统计 devfreq 相关 dmesg → 输出 PASS/FAIL 与日志目录 `e902/verify-logs/<ts>/`。

**判据**：心跳含 `0xE902C0DE`；控制台出现 `=== A733 E902 firmware v2 ===` 与 `[tick]`；PING 回 `0x02000001`；UART 计数 ≥4 且随注入增长。任何一步失败 → §5。

## 4. 回滚三梯队

| 梯队 | 场景 | 命令 |
|---|---|---|
| ①板上热回滚 | 板子能启动 Linux | `printf 'orangepi\n' | ssh_board.sh "sudo -S sh /home/orangepi/e902v2/restore-scp.sh /home/orangepi/e902v2/scp.fex /dev/mmcblk1"` → `sudo reboot` |
| ②读卡器恢复 | 板子起不来（卡在 bl31） | 卡插 TL101 读卡器 → `sudo bash e902/recover-sd.sh`（自动指纹识别并写回厂商 scp）→ 卡插回板子上电 |
| ③整头重写 | 引导头损坏 | `sudo dd if=e902/backup/sd-boot-head-20260922.img of=/dev/sdX bs=1M count=24 conv=notrunc`（读卡器上） |

回滚产物（全部经哈希校验，在 `e902/backup/`）：
- `sd-boot-head-20260922.img` 24MiB，sha256 `114cd1f3a792…`（= 厂商态引导头；**旧文件 sd-boot-head.img `665cd428…` 已过期，勿用**）
- `scp.fex.on-medium.bin` 105912B，sha256 `07e6b9762810…`（= 厂商 scp 原件）
- `board-boot-backup.tgz`（板上 /boot + /lib/modules）

注意：我们刷写后介质 24MiB 头哈希会变为 `a84c5c63…`（属预期，仅 scp 槽位内容不同）；恢复厂商件后头哈希应回到 `114cd1f3…`。

## 5. 故障矩阵（现象 → 恢复）

| 现象 | 根因 | 恢复 |
|---|---|---|
| 上电后大核串口打印 `bad checksum / bad magic / Loading boot-pkg fail` | boot0 校验启动包 add_sum 失败（T22：改槽位内容后必须重算） | 卡插读卡器 → `python3 e902/tests/fix-bootpkg-sum.py /dev/sdX --write`（厂商态应写回 a91ddf89） |
| 上电后 ssh 不通、大核串口静默（无 bad checksum 打印） | bl31 未收到合法 startup feedback（握手被拒）或串口未接 | 梯队②；确认 add_sum 已修（fix 脚本 check 应 PASS） |
| 板子启动正常，心跳块全 0 | 固件未执行（镜像结构错 / 校验漏） | 跑 verify_scpfw.sh + verify_failsafe.sh；核对槽位偏移 0x113BC00 与长度 |
| 心跳 seq 不涨（E902 卡死） | 时钟被门控 / 固件跑飞 | 读 RISCV_BGR：非 0x00010003 则写回 0x00010003；仍不涨 → 断电重启（介质未坏） |
| 大核 `dmesg` 出现 ddrfreq/devfreq 报错刷屏 | 厂商 SCP 职能已让渡（A3） | 软失败，无害但吵；可 `echo mem 不可用`；彻底消除需关 `AW_DMC_DEVFREQ` 重编内核 |
| `echo mem` 后醒不来 | suspend 依赖厂商 SCP | 只能断电重启；本工程下禁止 suspend |
| mailbox 发了没回应 | E902 未跑 / 中断号错 / FIFO 满 | 按序查：心跳 seq → 心跳 [12] mbox_irq 是否增长 → `0x0709406C/0x0300406C` 状态字 |
| PL_CFG0 读回与写入不符（MISMATCH） | 与 Linux 抢 PL_CFG0 | 固件只在初始化写一次并读回校验；重试或错峰（等 Linux 起完再刷写/复位小核） |

## 6. 已实测的异常事件（存档）

1. **T21 握手被拒（真实砖级事件）**：hdr=0 版本刷入 → 板子不启动 → 梯队②恢复成功（全流程 < 10 分钟，机械化）。这是「握手格式错误」的实弹验证，也验证了恢复链。
2. **T20 介质机械链路**：原样写回测试证实裸区可写、落点精确、读回校验有效、24MiB 头哈希不变。
3. **控制台通道**：翻转 PL2 时 FT232H 收到 10 字节（基线 0），观测链路实锤。
4. 待补（上电后执行 `e902/tests/drills.sh` 与 `rollback-drill.sh`）：E2 时钟门控冻核/复跑、E3 mailbox 洪泛、回滚+重部署双程演练。
