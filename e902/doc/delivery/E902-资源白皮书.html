§ 00结论速览

  1. “从 Linux 直接借用 E902”在硬件上不成立。软件可见寄存器里不存在 E902 内核复位位；RISCV_BGR bit0 只是内核总线时钟门控。High·三方
  2. 唯一可行路径是 bl31：启动时 bl31 把启动包里的 scp 条目载入 SRAM_A2 0x40004000、写 E902_RST_START_ADDR、释放复位，然后阻塞等待小核通过 mailbox 通道 3 上报 startup feedback。替换该条目即可让 E902 执行我们的固件。High·三方
  3. 握手包格式已从厂商固件反汇编逐字解出并两次独立复核：通道 3，线上序 [hdr=0x00900200][count=13][13×u32=0]。曾误判为 bl31 拒绝；T22 定案：当时真因是 boot0 对启动包整包 add_sum 校验失败（bad checksum），hdr 值从未被硬件验证。High·反汇编×2
  4. 失败安全设计：我们的固件把握手放在 main() 第一梯队（先于一切外设初始化），即使后续初始化全部失败，板子照常启动，最坏后果退化为「小核不可用」而非「变砖」。High·反汇编
  5. E902 独占：S_SPI(0x07092000)、S_UART0/1、S_TIMER0..3、S_MBOX 读侧；共享：SRAM_A2、双 mailbox 硬件、hwspinlock、MSGBOX0_BGR、CPUS_CFG 总线；绝对禁区：PL0/PL1（PMIC I2C）。High
  6. 接管 E902 的代价：DRAM 变频、suspend、PMIC 看护三类厂商 SCP 职能丢失（表现为 SMC 返回错误码的软失败）。Medium·源码推断
  7. SD 卡（板上 /dev/mmcblk1）是唯一可启动介质，scp 槽位 = 绝对偏移 0x113BC00、长度 0x19DB8=105912 字节；当前卡内已是我们的最终固件（读回校验通过），只差插卡上电。High·实测

bl31（闭源 monitor）是唯一能把 E902 从复位态放出来的一方：它把 scp 条目拷贝到 SRAM_A2 0x40004000，把 E902_RST_START_ADDR（0x07032204）设为入口，释放复位，然后调用 arm_svc_arisc_wait_ready() 等 E902 在 mailbox 通道 3 上报 startup feedback；等不到就一直挂在那里（板子表现为不启动）。u-boot 侧的调用面：bootm.c:409 的 ARM_SVC_ARISC_STARTUP = 0x8000ff10。

频率关系

  • CPU（大核）变频不经过小核：ccu-sun60iw2-cpupll.c 无任何 SMC 调用，大核自己写 PLL。
  • DRAM 变频经过小核：ccu-ddr.c:77 发 ARM_SVC_SUNXI_DDRFREQ SMC → bl31 → mailbox → SCP。我们接管 E902 后该链路断，属于 §14 A3 软失败。
  • S_SPI 模块时钟：固件固定选 DCXO 24MHz、M=N=0（/1），SPI 时钟用 CDR2 分频（500kHz 时 CDR2=23）。真实 SCLK 频率待示波器复核（B3）。P

§ 09厂商 SCP 固件的资源足迹（静态反汇编）

对 u-boot/v2018.05-sun60iw2/scp.fex（105912B）做 objdump -D -b binary -m riscv:rv32 --adjust-vma=0x40004000，抽取全部解析出的地址注释（脚本 doc/e902/scp_addrs.py）。

  • SRAM 内只碰自己的镜像/bss/栈（栈顶 0x4002F000）——没有外部 SRAM 握手标志 ⇒ 与 bl31 的握手只能走 mailbox。
  • 实际使用的 CPUS 域寄存器：STBY_PRCM/AHBS_CLK(0x0000)、APBS0_CLK(0x000C)、S_TIMER0_CLK(0x0100)、S_TIMER_BGR(0x011C)、S_PWM_BGR(0x013C)、S_MBOX_BGR(0x017C)、S_UART_BGR(0x018C)、S_TWI_BGR(0x019C)、S_IRRX_CLK/BGR(0x01C0/0x01CC)、RTC_BGR(0x020C)、RISCV_24M_CLK(0x0210)、PRCM 0x0244/0x0250(×12)/0x0254/0x0260、NMI_INT_EN(0x0324)、BUS_ACG(0x033C)、E902_CFG 区(0x07032001)、0x07050010/14/0220、S_UART0(0x07080080/84/A4)、S_TWI0 区、0x07090000 区。
  • 跨域访问：CPUX_MSGBOX(0x03004001)、0x030060A0、0x03000200/0160/0000；主 CCU MSGBOX0_BGR(0x02002744)、0x02003300..340、0x02002588。
  • 判定价值：SCP 碰过而 Linux 也用的 = 真共享（RISCV_24M、S_MBOX_BGR、MSGBOX0_BGR、S_TWI0→PMIC、S_UART_BGR）；它完全没碰的（S_SPI 0x07092000 区、RISCV_BGR 0x0701021C）= 可安全归小核独占。

出处：DESIGN-NOTES §3；M（反汇编推断，非厂商文档）。

E902 独占S_SPI 0x07092000 + S_SPI_CLK/BGR(0x0150/0x015C)、S_UART0/1 + S_UART_BGR(0x018C)、S_TIMER0..3 + S_TIMER_BGR(0x011C)、S_MBOX 读侧 + S_MBOX_BGR(0x017C)、CLIC/CLINT、PL2/PL3Linux 侧对应节点 disabled 或无客户端，固件可用可配，无需仲裁
共享·需克制SRAM_A2（双地址！）、CPUX_MSGBOX(0x03004000) 写侧、S_MBOX(0x07094000) 写侧(ARM)、MSGBOX0_BGR(主 CCU 0x0744)、hwspinlock、RISCV_24M_CLK(0x0210)、RISCV_BGR(0x021C)mailbox 按「谁写谁发」使用，ARM 侧直接怼寄存器（无内核客户端）；RISCV_BGR 属于「改错即冻核」项，只允许 drills.sh 的 E2 流程触碰；SRAM 访问一律走 awdevmem.py（强制地址换算）
大核独占·禁区PL0/PL1（PMIC I2C，S_TWI0）、CPUX 子系统外设、DRAM 布局、启动介质其余区域任何情况下不写；碰 PL0/PL1 可能伤 PMIC/硬件
让渡给固件的厂商职能DRAM 变频、suspend/resume、PMIC 看护（原 SCP 职能）接管后丢失；表现为 SMC 错误码软失败 + 可能的 devfreq 重试日志；echo mem 在本工程下不可用（会醒不来，需断电）

并发风险：PL_CFG0 读改写窗口（§07）、mailbox FIFO 满（固件发送带 100000 次有界自旋 + TX 空 FIFO 等待）、心跳块只由 E902 写 / ARM 只读（单向所有权，天然免锁；未来大载荷用 hwspinlock）。
